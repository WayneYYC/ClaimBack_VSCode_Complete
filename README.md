# ClaimBack — AI Chargeback Investigator

> **MONEY TALKS 2 · Full-stack VS Code project** — A local, fictional chargeback-dispute investigation system. No real card details, bank logins, transfers or submissions.

**Status:** Complete local frontend + backend, with a no-key deterministic Demo Mode. Live Nicrron and PRISM integrations are implemented but must be checked with **your own** credentials in your own network. Never represent local logs as verified PRISM proof.

## 1. Mac: open and run with VS Code

1. Download and unzip `ClaimBack_VSCode_Complete.zip`.
2. Open **VS Code → File → Open Folder** and choose **ClaimBack_VSCode_Complete**.
3. In VS Code choose **Terminal → New Terminal**, then enter:

   ```bash
   ./run.sh
   ```

4. The script sets up `.venv`, installs the small dependency set, creates `.env` (only if absent), then runs the server.
5. Open **http://127.0.0.1:8000** in Chrome or Safari.

**Important:** Do not open `frontend/index.html` directly in the browser. It makes API calls to the FastAPI backend, which must be running.

### If `./run.sh` says Permission denied

```bash
bash run.sh
```

### Manual alternative (Mac/Linux)

```bash
python3 -m venv .venv
source .venv/bin/activate
python -m pip install -r requirements.txt
cp .env.example .env
python -m uvicorn backend.app:app --reload --host 127.0.0.1 --port 8000
```

### Windows / VS Code

Run `run_windows.bat` from the project folder or run in Command Prompt:

```bat
python -m venv .venv
.venv\Scripts\activate.bat
pip install -r requirements.txt
copy .env.example .env
python -m uvicorn backend.app:app --reload --host 127.0.0.1 --port 8000
```

Needs **Python 3.10+**, an Internet connection for the first package installation, and a recent browser. No Node.js or frontend build process.

## 3. Set up Nicrron and PRISM for the hackathon

Edit `.env` in VS Code and add **your own** keys:

```ini
NICRRON_API_KEY=your_actual_key_here
NICRRON_MODEL=nicrron/auto
PRISMTRACE_HOST=https://prism.blockconvey.com
PRISMTRACE_API_KEY=your_actual_prism_key_here
PRISMTRACE_PROJECT_ID=your_actual_project_uuid_here
```

**Nicrron**: https://nicrron.ai/dashboard/keys — OpenAI-compatible chat completions run through `https://api.nicrron.ai/v1/chat/completions` in `backend/engine.py`. Key stays server-side. You may use the organizer's code `FINTECH-LPBMK` in Nicrron if still valid.

**PRISM**: https://prism.blockconvey.com/signup — the organizer's code is `MONEYTALKS#2`. Copy the API key from Settings → API Keys and project UUID from the Project settings. Direct HTTP trace and span ingestion is implemented in `backend/prism.py` using PRISM's published endpoints (`POST /api/traces`, `POST /api/spans/ingest`). This avoids requiring LangGraph/LangChain locally and still records each actual tool step. Live uploads are performed off the request thread; you can inspect `Agent activity → click run` for **queued/sent/error**, then verify actual ingest in PRISM.

Restart the server after updating `.env`, then select **Live — Nicrron + PRISM** in a case drawer. **Only Live mode calls Nicrron or sends PRISM traces.** A Live v1 workflow might fail before reaching the LLM; that specific failing run makes no Nicrron call and is labeled accordingly in PRISM metadata.

**Known limitation:** this build has been tested locally and against **mock** HTTP sponsor calls. We cannot truthfully claim the PRISM traces or live Nicrron model outputs are verified until you run it using real keys. Once configured, inspect the PRISM console to confirm traces and spans.

## 4. Money Operations PRISM proof plan

Go to **Reliability lab** in the web UI:

1. **Sessions (6+ steps):** Set Live mode. Run `CB-0001` with v2. Open that run in PRISM and verify the eight real workflow spans (`load_dispute`, `lookup_order`, `lookup_payment`, `lookup_shipping`, `lookup_support`, `reconcile_documents`, `apply_dispute_policy`, `write_response`). A local timeline is not sufficient proof.
2. **Alert:** In the PRISM dashboard set an alert on agent errors/error rate. Use the lab's **Run v1 failures** in Live mode. Verify the alert actually fires; the app cannot promise PRISM alert setup automatically.
3. **Root Cause:** In Live mode run v1 on `CB-0005`, `CB-0010`, `CB-0015`. These three sample cases are missing the tracking key; v1 intentionally raises `KeyError`, while v2 correctly returns `NEEDS_REVIEW`. Verify a Root Cause cluster in PRISM Intelligence and then re-run the same three cases using v2. A cluster is not guaranteed just because three local errors exist.

Organizers recommend more than 50 agent runs before clustering. You can generate **real endpoint runs** using:

```bash
# 51 failing live v1 runs; attempts real PRISM ingest, but v1 fails before Nicrron
python run_batch.py --mode live --version v1 --cases CB-0005,CB-0010,CB-0015 --repeat 17

# Same three cases after fix; these call Nicrron, and can consume credits
python run_batch.py --mode live --version v2 --cases CB-0005,CB-0010,CB-0015
```

**Do not** indiscriminately run large v2 live batches: they make paid model calls. Allow background PRISM uploads to finish before ending the server process. `Agent activity` can show last uploader status; the source of truth remains PRISM itself.

## 7. Scope and safety

This is a hackathon **prototype using only fictional/sample records**. It does not perform OCR, use Stripe, authenticate merchant accounts, verify source records with banks, predict guaranteed winning outcomes, move money, or file real disputes. It stores run and review data in a local SQLite file, not a production database. Do not expose this service to the public Internet or upload sensitive personal data. Before any production use you would need authentication, user permissions, data protection, robust document processing, processor-specific evidence rules, monitoring and security review.
